# 詳情圖片切換與載入修正

日期：2026-09-21。

## 問題與基準

詳情彈窗直接替換共用 `<img>` 的 `src`，沒有清除舊畫面，也沒有 loading／error／retry 狀態。新圖片下載尚未完成時可能繼續顯示上一件作品；下載失敗或停滯時，介面沒有恢復方式。需同時驗證圖片、標題與目前選取作品一致。

27 張詳情圖已是 WebP，最長邊最多 2048 px、品質 92，總計 9,450,350 bytes；最大 kakult 橫幅為 781,042 bytes。手機和桌面使用同一張大圖，未依實際顯示面積選擇來源。

## 修正範圍

1. 圖片切換建立獨立請求識別，立即清除上一張，正確作品的縮圖可先顯示；清晰圖解碼完成才替換。逾時與失敗可重試，較舊請求不能覆蓋較新的選取。
2. 使用 640／1024／最多 1440 px 的分級圖片，保留原有 2048 px 圖檔。1024 px 重用場景貼圖；依彈窗的實際可用尺寸、作品比例與最多 2 倍像素密度選擇，避免手機無條件下載大圖。
3. 目前作品優先；只在使用者準備開啟作品或目前圖片已完成後，有限度預載相鄰作品。快速切換或關閉彈窗時取消無用請求，失敗不永久留在快取；快取設上限。
4. 驗證首次開啟、快速切換、反向回應、關閉重開、失敗重試、預載重用及手機尺寸，最後推送並確認部署。

## 實作結果

- 開啟／切換作品時，標題、繪師、說明、媒材、展區、作品狀態、編號、頁碼與定位目標同步更新。圖片區立即清除上一件，再顯示目前作品的縮圖與載入狀態；清晰圖完成下載及解碼後才掛入畫面。
- 每次選取都有獨立版本識別；較舊的成功、失敗與關閉事件無法覆蓋新作品。圖片 15 秒逾時後可重試，清晰圖失敗仍保留正確縮圖。
- URL 共用進行中的請求與最多 8 張已解碼圖片。切換或關閉時取消不再需要的下載；目前圖片完成 350 毫秒後才依序預載前後兩件。目錄停留／聚焦 180 毫秒才嘗試預載該件；省流量及 2G／3G 連線不預載。
- 1024 px 圖片沿用已產生的場景資產；新檔採內容雜湊名稱。640 px WebP 品質 86、1440 px 品質 88，lllokkk 直幅的飽和紅色細線以 JPEG 4:4:4 品質 82 保存，已比較局部畫面。保留原始素材與既有 2048 px 相容圖，不放大低解析度來源。
- `prepare-artworks.py` 會同步分級圖片中繼資料至 `gallery.json`；Blender 匯出腳本也保留此欄位，往後重新建模不會退回單一大圖。

各級檔案統計如下；1024 px 為既有場景資產，較小來源不重複產生 1440 px 檔案。

| 最長邊 | 數量 | 中位數 | 最大檔案 |
| --- | ---: | ---: | ---: |
| 640 px | 27 | 48,212 bytes | 140,021 bytes |
| 1024 px | 27 | 100,760 bytes | 437,153 bytes |
| 最多 1440 px | 26 | 154,597 bytes | 542,053 bytes |

kakult 橫幅原為 2048 × 1403、781,042 bytes；新版本 640 × 438 為 95,370 bytes，1440 × 986 為 386,046 bytes。瀏覽器依圖片在彈窗中的實際佔用面積選擇，手機無須固定下載最大版本。

## 驗證

- `pnpm test`：38 項全部通過，新增 7 項涵蓋同步清除、回應順序顛倒、關閉重開、失敗重試、串行預載與重用、取消及逾時、快取釋放、尺寸選擇與所有衍生檔案的尺寸／大小限制。
- `pnpm build`：TypeScript 與正式建置通過。仍有既有的 Three.js bundle 大於 500 KB 提醒；此次 GLB 與模型配置未改動。
- 修正前實測：切到 Shiris 時標題與 `src` 已改變，`currentSrc` 仍為上一張 Virgil，且 `complete=false`，確認舊圖可在新請求等待時殘留。此觀察不能單獨證明使用者當次請求永久失敗的原因。
- 在正式建置的本機測試伺服器刻意暫停 DiDi 清晰圖，所有欄位立即改為第 02 件，舊圖清除，接著顯示正確 DiDi 縮圖；切到第 03 件後放行舊請求，仍維持第 03 件。暫停成江圖片後關閉並立刻重開第 20 件，也沒有被舊回應或關閉事件覆蓋。
- 對 kakult 橫幅回傳 HTTP 503：作品資料及縮圖正確，出現失敗訊息與重試按鈕；恢復服務後重試成功，錯誤狀態清除。
- 第 26 件完成後預載第 27 件，再切換時同步顯示已解碼的第 27 件，該來源請求數仍為 1。省流量模式另行驗證，場景貼圖完成後開啟新作品僅有目前作品的清晰圖請求，等待後沒有相鄰預載。
- 第 27 件的展區、作品狀態、圖片替代文字均與資料一致；實際按定位後彈窗關閉，小地圖標記符合其站位 `(3.535, 1.65, 0.75)`。模擬 WebGL context loss 時，已開啟彈窗的定位按鈕立即停用，作品資料仍可閱讀。
- 手機 390 × 844、模擬像素密度 3：仍以密度上限 2 選用 kakult 的 640 px 圖。在僅該清晰圖限制為 105 KB/s 的本機測試中，95,370 bytes 約 1.06 秒顯示完成；縮圖未套用限速，因此不以其顯示時間代表真實冷啟動效能。頁面與 viewport 均為 390 px，沒有橫向溢出。
- 一般流程與故障圖片測試沒有未處理的 JavaScript 錯誤；刻意模擬 WebGL 中斷會留下預期錯誤紀錄。未宣稱真實手機硬體與所有網路環境的載入時間。
